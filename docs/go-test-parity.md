# Go test parity checklist

Tracks every Python unit/system test function (≈127 unit tests across
`test/` and `test/unit/`, plus the systest suites) as one of:

- **ported** — the assertion was ported to a Go test (name the Go test).
- **Go-idiomatic** — replaced by a Go-native equivalent (e.g. `-race` tests
  replacing thread-interleaving tricks, `httptest` replacing `responses`).
- **dropped-with-reason** — Python-internals-only test with no Go
  equivalent; the reason is recorded.

Each task's builder updates its rows; Task 29 (final parity sweep) verifies
completeness. Table state is per migration commit.

Recorded deviation (user decision, 2026-10-09, extending the Task 3
review decision; NEWS in plan Task 28): the running-config writer —
like the state-file writer — uses Go 1.27's `encoding/json/v2`
encoder. The output is parsed-JSON-equal to Python's
`json.dump(..., sort_keys=True)` but **not byte-identical**: object key
order is Go-native (map iteration order — NOT sorted and NOT
deterministic across writes, so no test may assert a Go-written file's
key ordering and all comparisons are parsed-structure comparisons),
Python's 4-space json.dump layout is kept, floats render Go-native
(60.0 as "60", 1e-05 as "0.00001", 1e+20 as
"100000000000000000000"; Python: "60.0", "1e-05", "1e+20"), and
non-ASCII is raw UTF-8 where Python's `ensure_ascii=True` writes
\uXXXX. All parity assertions above compare parsed JSON, so none of
them depend on the byte-level difference.

Deviations and notes:
- **Sanctioned strict-at-load**: search/secret-filter construction errors
  that Python raises lazily (replacement-template compile at first
  substitution, unknown `unit_log_levels` severity names — Python KeyError
  at filter time) are rejected at construction with Python-equivalent
  messages.
- **Warn-and-disable (sanctioned, charter §2)**: patterns using
  RE2-unsupported constructs are Python-valid, so they cannot be
  rejected; the filter is disabled with a startup warning.
  Python-INVALID patterns keep Python's hard error.
- **Unmatched and empty named groups** in searches: Python's `groupdict`
  yields `None` for an unmatched group (dropped by `make_tags`) and `""`
  for a matched-but-empty one (emitted as `tag=` in the datagram). Go's
  RE2 cannot distinguish a matched-empty group from an unmatched one, so
  BOTH are dropped here — the metrics-visible delta is limited to
  matched-empty groups of optional groups that did not capture text.
- **Crash-free runtime tolerance (sanctioned, charter §2)**: malformed
  entry values that crash Python mid-run (truthy non-string MESSAGE in
  the secret-filter/apply paths, non-numeric PRIORITY, non-string unit,
  float/exotic search field values) are tolerated by Go — the value is
  left untouched or the field does not match, and processing continues.
- **Tagged name-class skew**: Go `[\pL\pN_]` is a SUPERSET of Python
  `\w` — Go's newer Unicode tables classify 4657 additional codepoints
  as letters/numbers that Python's `\w` misses (no codepoint is
  matched by Python but not Go), so no tag NAME that Python keeps is
  dropped and vice versa is impossible; extra Go-kept names only appear
  for astral/rare codepoints. The `\s`/value class is exact. No
  differential test is committed; the sweep that produced the 4657
  count is not part of the repository.
- **Nested bracket classes in globs**: Python 3.12+'s `re` parses a
  nested class (`[a[b]`) as the union `{a, b}`; the Go port translates
  the glob text for RE2, which parses the same text as `{a, [}`. This
  affects only pathological unit-level globs — no differential row
  covers it and Python itself changed this behavior across versions.
- **`search.setdefault` mutation**: Python mutates the parsed config
  (running-config dump gains empty `"tags"`/`"fields"` keys on
  searches lacking them); Go does not mutate the parsed document.
- **Regex engine semantics**: RE2 ASCII `\w`/`\s`/`\d`/`\b` in user
  patterns (spec §5 sanctions stdlib RE2 semantics); the Tagged
  sanitization classes are covered above (value class exact, name class
  a documented superset skew).
- Python's `lru_cache` on `_unit_match_level_glob` is pure memoization
  and is not reproduced.

Deviations and notes:
- **Crash-free ip_to_geohash failure paths (sanctioned, charter §2 —
  user decision 2026-10-09, Task 6 review, extending the runtime
  entry-value tolerance)**: Python raises mid-run for every failure
  mode — `int(precision)` ValueError, missing tag KeyError, geoip2
  AddressValueError (invalid IP string), AddressNotFoundError (IP not
  in the DB), AttributeError when a record has NO location object
  (`loc.latitude` on None), and geohash's ValueError for out-of-range
  coordinates. The DIVERGENCE IS NOT JUST THE ERROR HANDLING: Python's
  `read_single_message` (journalpump.py:1011-1018) catches those
  exceptions at the read-loop boundary, logs "Unexpected exception
  while handling entry for %s", emits `stats.unexpected_exception`,
  sleeps 0.5 s and DROPS the entry; Go returns "" for the geohash tag
  and FORWARDS the entry (whose search still matches, so the hit
  counter and the increase metric fire). Forwarded-with-empty-tag vs
  dropped-with-unexpected-exception is the user-approved delta.
- **Precision parsing deltas** (`int(args[1])` vs `strconv.Atoi`):
  Python int() accepts underscores ("1_0" == 10) and
  arbitrary-precision literals; Atoi rejects both, so those configs
  return "" in Go where Python geohashes (with precision 10, or an
  absurdly large precision). Ordinary "5"-style args parse identically.
- **Reload quirk (replicate, do not fix)**: Python's handle_new_config
  (journalpump.py:957-965) never resets `self.geoip` — a reloaded
  config that omits `geoip_database` keeps the previous database open
  across reloads, forever. The Task 16/17 pump wiring must do the same.
- **Tag callable evaluation order — no deviation**: Python evaluates
  the tags dict in config document order (journalpump.py:629-634);
  encoding/json's map decode discards key order, so the config layer
  captures it from the raw JSON (a token walk →
  `ReaderConfig.SearchTagOrder`) and `PerformSearches` iterates the
  ordered tag list, keeping earlier tags visible to later callables.
  Documents without captured order (synthetic test maps) fall back to
  sorted keys — deterministic, and not parity-relevant because they
  never come from a real config file.
- **No-DB behavior is Python-faithful, not "fixed"**: `geoip_database`
  unconfigured → Python returns "" (the config keeps working with empty
  geohash tags) and Go does the same (`self.geoip is None`
  short-circuit). Spec risk 9 (silently empty tags from a forgotten
  port) is guarded by construction instead: the tag-function registry is
  wired per Searcher and `NewSearcher` rejects a search referencing an
  unwired function.
- **Absent vs zero coordinates are exact**: geoip2-golang/v2 exposes
  Latitude/Longitude as pointer fields, so a PRESENT (0.0, 0.0) record
  produces `s0000000` like Python while an absent location returns ""
  (the fixture has both).
- **Subnormal latitude**: Python's `_float_hex_to_int` asserts on
  subnormal `latitude/90` (AssertionError mid-run); Go's `Encode`
  returns an error for the same inputs (unreachable through
  `ip_to_geohash` for practical GeoIP data).
- **Huge longitudes**: Python wraps with a subtract-360 loop; the loop
  is ported verbatim (identical float results; absurd magnitudes would
  loop in Python too, and GeoIP records cannot produce them).

## Task 7 — statsd client (raw UDP, telegraf tags) and persistent gauges

Source of truth: `journalpump/statsd.py`; consumer seam: `internal/statsd`
(`Client`, `PersistentGauges`). Go tests: `internal/statsd/statsd_test.go`
(golden datagram bytes captured on a loopback UDP socket), plus the port of
`test/unit/reader/test_stats.py::test_persistent_gauge`.

- **Wire format is byte-faithful, verified against the real client**: the
  golden expectations were generated by stubbing `StatsClient._socket` and
  running the actual `journalpump.statsd` code — `m:1|c`, float gauges with
  Python `str(float)` repr (`60.0`, `1e-05`), int gauges as plain decimal
  (`123`), timing `...|ms`, prefix prepended to the metric name.
- **Tag order on the wire is REVERSED, ported exactly**: Python inserts every
  tag at index 1 (`statsd.py:55`), so merged order `[a, b]` lands on the wire
  as `,b=..,a=..` after the metric name. The Go client walks the merged order
  backwards for the same result (probe-confirmed).
- **Global tag order is exact, no deviation**: the config layer captures the
  `statsd.tags` document order from the raw JSON (same token-walk machinery as
  the search tag order, `captureTagOrders` → `StatsdConfig.TagOrder`) and the
  client emits the global tags in that order — Python's dict order. A nil
  captured order (synthetic client construction) falls back to sorted keys;
  the golden tests pin both behaviors.
- **Per-call tag ORDERING deviation (sanctioned, recorded)**: per-call tags
  arrive as `map[string]string` (from `Tagged.make_tags`), whose insertion
  order is unrecoverable, so NEW per-call keys are appended after the globals
  sorted among themselves; an override keeps the global position with the
  per-call value (Python `dict.update` semantics, exact). Coordinator
  decision (2026-10-09, Task 7 review): sanctioned — metric values identical;
  telegraf treats the tag list as a set; ordering unobservable in stored data.
  NEWS-recorded (Task 28). Exception: `UnexpectedException` knows its
  insertion order (exception, where, then caller keys) and reproduces it.
- **Int vs float gauges**: Python's single `gauge()` calls `str(value)` on
  whatever it gets — `journal.read_lines` (int) renders "123" while
  `journal.last_read_ago` (float) renders "0.123". Go splits this into
  `GaugeInt` (Python int call sites) and `Gauge` (Python float call sites,
  reusing `journal.PythonFloatRepr`). Call-site mapping: read_lines,
  read_bytes, sent_bytes, sent_lines, journal.status, persistent gauges and
  every `increase` are int; last_read_ago, last_sent_ago,
  perform_search_regex_duration and timing are float.
- **No sanitization in the client, matching Python**: sanitization lives at
  the `Tagged.make_tags` call sites (internal/tagged, Task 5); statsd.py
  formats whatever it receives.
- **No sampling**: statsd.py has none — every send emits one datagram.
- **Disabled client is exact**: `None in self._dest_addr` → a missing host OR
  port disables every send (the config decode models host PRESENCE with
  `*string`: nil = the key is absent). An explicitly EMPTY host is enabled,
  like Python: CPython's setipaddr special-cases the empty host to INADDR_ANY
  (0.0.0.0) without calling getaddrinfo — which would raise [Errno -5] — so
  `sendto(("", port))` sends to 0.0.0.0 and the kernel delivers locally. Go
  resolves the empty host to a nil IP and substitutes 0.0.0.0 (golden-tested
  against a loopback listener).
- **Send failures log, never crash**: Python catches `OSError` around
  `sendto` and logs `"Stats UDP send failed: %s"` at INFO (statsd.py:59-60);
  Go does the same around the lazy address resolution and the unconnected
  `WriteToUDP`. An UNCONNECTED socket is used deliberately — a connected one
  would surface ICMP "connection refused" errors that Python's `sendto` never
  sees.
- **`exception` tag value deviation**: Python uses `ex.__class__.__name__`
  (e.g. "OSError"); Go has no exception classes, so the tag carries the
  error's dynamic type name via `reflect.TypeOf` (e.g. "fs.PathError"). A nil
  error (Python would crash on `ex.__class__`) renders "error" so the counter
  still fires. Metric name ("exception"), `where` tag and counter semantics
  are identical.
- **UDP family is udp4, matching Python's AF_INET**: `ResolveUDPAddr("udp4", …)`
  + `ListenUDP("udp4", nil)` make an IPv6-literal host fail resolution exactly
  like Python's AF_INET `getaddrinfo` (an OSError subclass, caught and logged
  at statsd.py:59-60) instead of sending successfully.
- **Persistent gauge semantics are exact** (journalpump.py:313-324 ported as
  `PersistentGauges.Set`): the (value, tags) pair is always recorded; a zero
  is emitted only on the transition from an existing non-zero value; non-zero
  values are never emitted by Set (the pump batches them). The pump-level
  `refresh_gauges` resend loop (journalpump.py:1104-1109) is
  `RefreshNonZero`: re-emits only non-zero values. `test_persistent_gauge` is
  ported step-for-step (sequential subtests — the state accumulates).
- **Consumer-side seam for Task 10**: `filter.Stats` now carries the counter
  value (`Increase(metric, incValue, tags)`) so `*statsd.Client` satisfies it
  directly — perform_searches uses Python's default inc_value=1 explicitly;
  the reader-side persistent gauges go through `GaugeSender`/`GaugeInt`.

## Task 8 — state file I/O (D3)

Source of truth: journalpump.py save_state/load_state/get_state
(journalpump.py:1057-1073, 987-995, 326-335) and senders/base.py
Sender.get_state (base.py:166-185); Go port: `internal/state`. The
Python-written fixture is committed
(`internal/state/testdata/state_python_written.json`, generated by
`generate_fixture.py` through the REAL `JournalReader.get_state`,
`LogSender.get_state` and `JournalPump.save_state` code paths with a
pinned monotonic clock), the Go-written fixture
(`state_go_written.json`) is read by the permanent pytest
`test/test_state_file_interop.py`.

- **Parsed-equal in both directions, proven order-independently**
  (sanctioned deviation, user decision 2026-10-09 — charter §2):
  `TestWriteRoundTripParsedEqual` re-writes the decoded Python fixture
  and asserts the PARSED document equals the original's — the Go writer
  uses Go 1.27's `encoding/json/v2` encoder and emits Go-native JSON,
  NOT `json.dump(indent=4, sort_keys=True)` bytes: object key order is
  Go-native (struct declaration order, and map keys in Go map iteration
  order — not sorted and NOT deterministic across writes; the writer's
  senders dedup to a name-keyed map with last-value-wins, matching the
  parsed semantics of Python's dict), non-ASCII strings are raw UTF-8
  instead of ensure_ascii escapes, and `health.elapsed` renders
  Go-native (12.5 → 12.5, 0 → 0). Kept from Python: the parsed document
  is equal, the 4-space json.dump layout (items on their own lines,
  empty containers as `{}`/`[]`), no trailing newline, file mode 0600,
  and the lenient write-only raw fields are inlined (whitespace
  re-indented under indentation, values preserved). Deviation BOUNDARY
  (probed): non-finite floats (NaN/±Inf) are an encoding error in v2
  ("unsupported value: NaN") where Python's json.dump default
  (allow_nan=True) emits NaN/Infinity literals — unreachable from
  journalpump's own paths (decoded state carries only RFC-valid JSON
  values; a Python-written NaN literal fails Go's decode as well —
  every field, including the lenient raw `start_time` path, is read
  through encoding/json's decoder, which rejects the literal,
  probe-confirmed), but a state value that is not valid RFC JSON
  cannot be re-encoded by the writer. `TestWriteParsedRoundTrip`
  replaces the old byte-golden lock: the fresh write parses exactly
  like the committed `state_go_written.json` artifact and re-reads to
  the same logical state compared with senders keyed by NAME — no
  assertion may depend on a Go-written key order (the committed
  artifact still exists only as the Python interop test's input;
  regenerate with `UPDATE_STATE_GOLDEN=1 go test ./internal/state/`).
  The WIRE-path serializer (`internal/journal`) keeps Python
  byte-faithful output — that path is byte-parity-critical and
  unaffected.
- **Ordered decode is quirk-critical, no deviation**: the resume loop
  iterates `reader_state.get("senders", {}).items()` in FILE key order
  (journalpump.py:890-905) — the LAST listed sender wins and any null
  `sent.cursor` aborts with a full resync. `internal/state.Read`
  token-streams the per-reader senders object into an ordered slice
  (everything else decodes order-insensitively; only the senders order
  is order-sensitive). `TestResumeCursorLastListedWins` locks the quirk
  with a hand-crafted file whose last-listed sender is not the
  alphabetically last (captured Python-written files are always
  alphabetical and cannot exhibit it).
- **Malformed senders crash exactly where Python crashes**: Python's
  unconditional `sender["sent"]["cursor"]` (journalpump.py:895-896)
  raises KeyError only when the walk REACHES the sender. The decode is
  lenient; the missing-sent.cursor error surfaces from
  `ResumeCursor` (which returns `(cursor, error)`) at the walk
  position: a malformed sender under a reader NOT in the new config is
  never walked and harmless, and a malformed sender AFTER a
  null-cursor sender yields a full resync, not an error (the
  break-on-null abort at journalpump.py:904). Locked by
  `TestResumeCursorMalformedSenderCrashesAtWalkPosition`,
  `TestResumeCursorMalformedAfterNullIsFullResync` and
  `TestMalformedSenderUnderUnconfiguredReaderIgnored`.
- **Write-only fields decode leniently, no deviation**: searches hit
  counters, total_lines, total_bytes, start_time and buffer.cursor are
  never read back in Python, so they decode as raw JSON bytes and the
  writer re-emits them verbatim — Go accepts any value Python could
  have written (float hit counters, huge ints, non-string start_time;

## Task 14 — per-sender buffer and reader backpressure (MsgBuffer port)

`internal/buffer` ports `senders/base.py:MsgBuffer` and the reader
backpressure of `journalpump.py:210-244, 1019-1043` as a
channel-per-sender handoff (spec §4.3): the sender loop consumes the
buffer's channel (its `len` is the flush trigger — the same signal

the worst-sender `Gate` (`WriteLimitCount` / `WriteLimitBytes`,

nothing is ever dropped (`Enqueue` retries on the context), no

  dequeue observer — `TestDrainOpensGate` pins that a raw receive

  (`TestGateLimits`); the `_failed_senders and not senders → 0`

### Task 19 review round 1 (changes-required)

- **Retry classification — Python-exact (not a Python-bug fix).** Core
  ruling: reproduce Python's actual `_should_retry` (rsyslog.py:211-216)
  rather than "fixing" the suspected bug. Python checks
  `isinstance(ex, OSError)` FIRST and returns
  `errno in (EPIPE, ECONNRESET, ETIMEDOUT)`; the `ssl.SSLEOFError`
  branch after it is unreachable, because `ssl.SSLEOFError` IS an
  `OSError` subclass and its errno is not one of the three. So Python
  does NOT retry an SSLEOFError. `shouldRetry` therefore matches only
  EPIPE / ECONNRESET / ETIMEDOUT; the earlier SSLEOF-via-
  `io.ErrUnexpectedEOF` mapping was wrong and removed.
  `TestShouldRetryMatchesPython` and the retry/no-retry write-count
  tests pin this.
- **CUSTOM `%structured-data%` nil → `"None"`.** Python's
  `str.format(**kwargs)` renders a `None` value as the four characters
  `None`, while `""` renders empty. `customSD` reproduces that; the
  fixture now carries CUSTOM sd nil/""/present oracle cases.
- **`max_msg` edge values.** Only the falsy `0` falls back to 2048
  (`max_msg or 2048`); negatives are preserved and applied as Python
  negative slice indices (`message[:-k]`). `pySliceEnd` implements the
  Python semantics for both framings and for the `len(message) >=
  max_msg` truncation test. Fixture cases and
  `TestFramingNegativeAndZeroMaxMsg` pin it (non-vacuity proven by
  clamping negatives to 0).
- **UTF-8 replacement.** The formatters emit
  `s.encode("utf-8", "replace")` over journal bytes decoded with
  surrogateescape: each byte that is not valid UTF-8 becomes ONE `?`
  (a valid U+FFFD passes through). `encodeUTF8Replace` implements this
  and runs BEFORE framing, so a replaced byte counts once toward
  truncation byte-length (`TestEncodeUTF8Replace`,

### Task 19 review round 2 (changes-required)

- **AfterFunc race — connection retirement.** `context.AfterFunc`'s
  `stop()` does NOT wait for an already-started callback, so a
  cancellation racing a completed write could leave `Send` returning
  success while the callback then forced an expired write deadline onto
  the RETAINED connection, poisoning later sends.
  `writeWithContext` now returns whether the callback fired and waits on
  a done channel (`stop()` false → `<-done`) so no deadline write can
  race the caller after return; when the callback ran on a completed
  write, `Send` retires the connection (closes it) so the next send
  reconnects cleanly. `TestSendCancellationRacingCompletedWriteRetiresConn`
  is deterministic (cancels from INSIDE the first Write) and asserts the
  deadline callback ran, the connection was closed and a later send
  reconnects (non-vacuous: disabling the retirement leaves the poisoned
  socket retained).
- **`max_msg == math.MinInt` overflow.** `max_msg - 1` in Go int
  overflows to a large POSITIVE bound at MinInt, sending the whole
  message plus a newline where Python's arbitrary-precision arithmetic
  yields the newline alone. `maxMsgMinusOne` saturates at MinInt.
  Covered by `TestFramingNegativeAndZeroMaxMsg` (int64 extremes) and a
  `-(2**63)` oracle case in the fixture.
- **Independent fuzz oracle.** The fuzz expectation no longer calls the
  production `pySliceEnd` (which also repeated the overflowing
  subtraction, validating the implementation against itself). It
  reimplements Python's framing independently (`oracleFrame` /
  `pythonSlice`), including the `max_msg or 2048` zero normalization and
  int64-extreme saturation, while keeping the advertised-octet-length
  desync check. The MinInt seeds fail against the overflowing
  implementation.
- **Deterministic cancellation test.** The cancellation worker-
  termination test no longer sleeps; the blocking stub signals when
  `Write` is ENTERED, and the test cancels only after observing it, so
  `Send` cannot pass by returning at its initial canceled-context check.

(`logging.getLogger(f"LogSender:{reader.name}")`) is now carried on

Payload mapping (rsyslog.py:78-100): facility = `int(SYSLOG_FACILITY)`
with the list first-element rule and an IndexError/TypeError/ValueError
fallback to `default_facility`; severity = the UNGUARDED
`int(message.get("PRIORITY", default_severity))` (a non-int PRIORITY is
the error path); timestamp = `raw[:26] + "Z"` for a truthy `timestamp`,
else a WARNING plus `datetime.now(UTC).strftime("%Y-%m-%dT%H:%M:%S.%f")
+ "Z"`; appname = the nested
`SYSLOG_IDENTIFIER → SYSTEMD_UNIT → PROCESS_NAME` default chain; pid =
the truthiness-then-`str()` rule (falsy → NILVALUE); msg = MESSAGE.
The journal payload is decoded with `json.Decoder.UseNumber()` so an
INTEGER field (JSON `100`) keeps its integer identity instead of
collapsing to float64 and rendering "100.0" — Python's `json.loads` yields
`int(100)` and `str(100) == "100"`, while a float field keeps its fraction.
`TestNumericFieldsKeepIntegerIdentity` and the captured
`numeric_pid_and_fields` wire case pin it.

Error classification and reconnection:

- The per-sender classifier (Task 13's `retriable(error)` seam) is
  installed via `Instance.Classifier`: `RSYSLOG_CONN_ERRORS`
  (`socket.timeout`, `ConnectionRefusedError`, `TimeoutError`) → the
  silent retriable path; anything else → Python's generic
  `except Exception` path (`mark_disconnected`, `unexpected_exception`
  stats, backoff, re-init). `TestInstanceClassifierRoutesConnErrors`
  proves the classifier is installed and routes both ways.
- Connection transitions and backoff are owned by the shared Task 13
  loop, not the sender, but the sender's connect path runs INSIDE
  `SendMessages`, so it reports its transitions through a new OPTIONAL
  transport seam, `sender.ConnectionReporter`
  (`SetConnectionObserver(connected, disconnected)`), detected in
  `NewLoop` exactly like the existing `DurableReporter` capability:
  - A SUCCESSFUL connect reports `connected` → the loop's `MarkConnected`
    clears the health errors and RESETS the shared backoff exponent,
    matching Python's `mark_connected` at the end of
    `_init_rsyslog_client`. Without it, repeated payload failures
    separated by successful reconnects (e.g. a list-valued PRIORITY that
    drops the client each time) kept escalating toward the 1800 s cap
    instead of restarting at the attempt-1 backoff.
    `TestLoopReconnectResetsSharedBackoff` runs the REAL `sender.Loop`
    (synctest fake clock): every attempt connects then fails its payload;
    the test requires ≥8 attempts in 10 s, which only holds when each
    connect resets the exponent (non-vacuous: removing the observer
    wiring drops it to ~4).
  - A RETRIABLE connect failure reports the ORIGINAL error →
    `MarkDisconnected` BEFORE the flat 5 s wait (rsyslog.py:62-70 marks
    disconnected, then sleeps), so the failure is in the health ring
    immediately and a cancellation during the wait cannot replace it with
    `context.Canceled`; the sender then returns the original error so the
    loop applies its jittered exponential backoff on ONE shared counter on
    top of the flat sleep. The sender keeps no private backoff state.
    `TestInitRetriableFailureCancelledDuringSleep` asserts the recorded
    and returned error is the original `ECONNREFUSED`, not
    `context.Canceled`.
  - A non-retriable failure (e.g. a missing `rsyslog_server`) returns
    immediately for the unexpected-exception path; the 5 s wait is a
    cancelable seam so shutdown never hangs.
  `TestSendFailureRefusedReconnectThenSuccess` (send failure → refused
  reconnect → successful reconnect, with the flat 5 s sleep and a
  retriable classification) and
  `TestInitLoopNonRetriableReturnsImmediately` pin the rest.
- On any send failure the client is dropped so the next attempt
  reconnects (Python's `close()` + `= None`); the shared loop owns the
  batch hold/backoff/retry.
- CA configuration validation: `ca_certs` presence is preserved so an
  explicitly empty string still selects TLS (Python's `cacerts is not
  None`, rsyslog.py:135), and a truthy NON-string value (e.g. `1`) is
  REJECTED with an error instead of being silently mapped to an empty
  cafile (system roots) while still selecting TLS — Python's
  `ssl.create_default_context(cafile=1)` raises. The sanctioned wrong-type
  deviation permits earlier rejection, not silent acceptance.
  `TestNonStringCACertsRejected` and `TestEmptyCACertsStillSelectsTLS`
  pin both halves.

### rsyslogd systest — process-spawn driver + a flagged ordering divergence

`systest/test_rsyslog.py` is ported off the in-process `JournalPump` onto
the Task 10 harness: the journalpump BINARY is spawned
(`JOURNALPUMP_BIN` selects Python or the Go binary) and the 5
parametrized cases inject into journald with `systemd.journal.send` and
assert the rsyslogd logfile, so both implementations run the same
black-box suite. The Python in-process helpers (`journalpump_initialized`,
manual `request_stop`) are replaced by the harness's READY=1 wait and
SIGTERM.

**Startup-delivery fix — first poll is immediate (no open-before-READY
change).** An earlier draft of this note claimed Python opens the journal
before its first READY=1; that is FALSE. Python's `JournalReader.__init__`
leaves `journald_reader` None (journalpump.py:204) and `update_status`
opens it inside `run`, after BOTH READY=1 notifications (daemon.py:113-114;
journalpump.py:1143-1179). READY=1 therefore precedes reader-open in both
implementations, and with `initial_position: "tail"` a line injected
before the reader attaches is skipped by both.

The real Go divergence the ported driver exposed was an EXTRA delay: the Go
reader slept a full `pollInterval` before its first open (the
`journaldReader == nil` branch), while Python's run loop starts with
`poll_timeout_ms = 0.0` (journalpump.py:1104) and opens the reader on the
immediate first poll. Combating that by moving reader-open before READY
would NOT reproduce Python and would be a separate lifecycle improvement
requiring adjudication; it was not done. Instead the daemon's first loop
iteration now polls immediately (`ReaderRuntime.run`), matching Python.
Verified directly before the fix: a line injected ~0.2 s after start was
lost, one at ~1 s delivered; after the fix the reader attaches on the first
iteration. The regression guard is
`TestRunLoopOpensReaderWithoutInitialPollDelay`, which fails (ensureCalls
stays 0 after `synctest.Wait()`) if the initial delay returns — independent
of the systest driver.

The ported driver still waits for reader attachment with a bounded probe
(`_wait_for_reader_ready`): like the original driver's
`journalpump_initialized()`, the tail-positioned reader must be attached
before the real batch, in EITHER implementation. The probe would also mask
a returning initial delay, so it does not stand alone — the daemon
regression guard above is the authoritative check.

## Task 21 — logplex sender (spec §5, D6)

`internal/sender/logplex` ports `journalpump/senders/logplex.py`: a
fire-and-forget HTTP POST. It is registered as output_type `logplex`.

Frame and config:

- Each message maps to `"<190>1 <format-now> <hostname> <token> <pid> - -
  <MESSAGE>"`, prefixed by its byte length (logplex.py:20-29). PRI is
  always 190; msgid and structured-data are the literal `-`; the timestamp
  is the FORMAT time (`now(UTC)`) in `%Y-%m-%dT%H:%M:%S+00:00 ` shape, not
  the journal timestamp.
- The named quirk-lock: `entry.get("_HOSTNAME", "localhost")` /
  `entry.get("_PID", "localhost")` never match because the journal
  processor strips leading underscores before the sender sees the payload
  (journalpump.py:708-714), so hostname and pid are the literal
  `"localhost"` even when the payload carries `HOSTNAME`/`PID`.
  `TestHostnamePIDAlwaysLocalhost` pins it.
- `New` requires `logplex_log_input_url` and `logplex_token` (Python's
  `config[...]` KeyErrors), reads `max_send_interval` (default 5.0) and
  `logplex_request_timeout` (default 2 s), and sets `ConnectOnInit` because
  `LogplexSender.__init__` calls `mark_connected`. The production HTTP
  client disables TLS verification (`verify=False`, deliberate, spec §2)
  and applies the per-request timeout.
- `MESSAGE` is unguarded in Python (`entry["MESSAGE"]` → KeyError when
  absent; `str +=` → TypeError when non-string); `formatMsg` returns an
  error for both, and for invalid JSON.
  `TestMissingMessageIsAnError` pins it.

Framing deviation (charter §2/D6, user decision 2026-10-09):

- Python's `format_msg` f-strings the ENCODED packet
  (`f"{len(pkt)} {pkt}"` with bytes `pkt`), so the PYTHON wire carries the
  bytes repr `b'...'` after each length prefix (len+3 characters on the
  wire). This is a real Python bug. Go sends the CLEAN RFC frame and does
  NOT reproduce it.
- Go's content parity is therefore asserted STRUCTURALLY against the Task
  11 fixture's repr-STRIPPED frame list
  (`systest-go/fixtures/logplex.json`, regenerated by
  `systest/test_groundtruth_logplex.py` with `GROUNDTRUTH_UPDATE=1`): the
  parsed fields (PRI, version, timestamp shape, localhost hostname/pid,
  token, msgid/sd, message) must equal what Python intends, and the clean
  frame must contain no `b'`.
  `TestFixtureStructuralParity` + `TestFormatMessageCleanFrame` pin it
  (non-vacuous: reproducing the repr makes both fail).

Fire-and-forget quirk lock:

- `SendMessages` posts once with Basic auth (`token`/token),
  `Content-Type: application/logplex-1`, `Logplex-Msg-Count` = batch length,
  and IGNORES the response status (no `raise_for_status`, always marks the
  batch sent — logplex.py:31-48). A 500 must not retry or disconnect.
- `Test500DoesNotRetryOrDisconnect` runs the REAL `sender.Loop` with a fake
  doer returning 500 and asserts exactly one request, `sent.count == 1`,
  and `health.status == "connected"`.
- `TestSendPostsHeadersAndBody` / `TestHTTPServerEndToEnd` pin the POST
  headers and body against a fake doer and a real `httptest` server.
